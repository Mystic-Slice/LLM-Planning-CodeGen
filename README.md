# Code-Driven Planning in Grid Worlds with Large Language Models

Supporting code and data for the paper ***Code-Driven Planning in Grid Worlds with Large Language
Models*** (Iterative Programmatic Planning, IPP).

The repository contains every LLM-generated policy program, every per-instance result file, and all
the scripts needed to **(a)** reproduce the result tables directly from the checked-in data and
**(b)** regenerate that data from scratch.

---

## TL;DR — reproduce the tables in the paper

```bash
# 1. create the environment (exact versions used in the paper)
conda create -n code-gen python=3.10.14
conda activate code-gen
pip install -r requirements.txt

# 2. open and run the results notebook (Kernel -> Restart & Run All)
jupyter notebook view_results.ipynb
```

[`view_results.ipynb`](view_results.ipynb) reads the result CSVs that are already in the repository
and rebuilds **Tables 1–4** of the paper. Each table is preceded by a markdown cell
explaining exactly which files and metric it uses.

## Repository layout

| Path | Benchmark | Contents |
|------|-----------|----------|
| `grasp_direct_code_gen/`     | GRASP     | Direct Generation, Pseudocode Extension and Step-by-Step policy programs + their results |
| `grasp_iterative_refinement/`| GRASP     | Iterative Refinement (IR) policy programs (one per refinement iteration) + results |
| `minigrid_unlock/`           | MiniGrid  | Unlock task: policy programs, `run.ipynb`, and `metrics_unlock.csv` |
| `minigrid_doorkey/`          | MiniGrid  | Door-Key task: policy programs, `run.ipynb`, and `metrics_doorkey.csv` |
| `minigrid_unlock_pickup/`    | MiniGrid  | Unlock-Pickup task: policy programs, `run.ipynb`, and `metrics_unlock_pickup.csv` |
| `llm_solve_baselines/`       | both      | Non-code prompting baselines: Naive Prompting, CoT, 2-step CoT |
| `view_results.ipynb`         | —         | **Consolidates all results into Tables 1–4** |
| `costs.csv`                  | —         | Per-instance API cost per (model, method, task), used by Table 2 |
| `requirements.txt`           | —         | Exact package versions from the conda env |

Inside each `grasp_*` folder:
- `model_codes*/` — the Python `solve()` functions generated by each LLM (the *policies*).
- `run.py` — executes those policies on every GRASP grid × configuration, writing one JSON file per
  instance under `all_results/`.
- `eval.py` — scores those JSON files (computes net energy) and writes the consolidated
  `all_results/results_<method>.csv`.

## Configuring LLM access (API tokens)

All models are accessed through the [OpenRouter](https://openrouter.ai) API using the OpenAI SDK
(`llm_solve_baselines/openrouter.py`). Configuration is via a `.env` file in the repository root:

```bash
# .env  (create this file in the repo root — it is read by python-dotenv)
OPENROUTER_API_KEY=sk-or-your-key-here
```

The model is selected inside each runner script by editing the `MODEL` variable, e.g. in
`llm_solve_baselines/run_grasp_bench.py`:

```python
MODEL = 'openai/o3-mini'          # GPT-o3-mini
# MODEL = 'openai/gpt-4o'         # GPT-4o
# MODEL = 'google/gemini-2.5-pro' # Gemini-2.5-Pro
# MODEL = 'anthropic/claude-3.7-sonnet'
# MODEL = 'deepseek/deepseek-r1'
```

The six models used in the paper are GPT-4o, GPT-o1, GPT-o3-mini, Claude-Sonnet-3.7, Gemini-2.5-Pro
and DeepSeek-R1.

## Which script/notebook produces which table

`view_results.ipynb` is the single entry point for all four quantitative tables. The table below
maps each table to the **result files it consumes** and the **scripts that regenerate those files**.

| Table | What it reports | Consumed by `view_results.ipynb` | Regenerated by |
|-------|-----------------|----------------------------------|----------------|
| **Table 1** | DG vs. IR, 6 models × 4 tasks | `grasp_direct_code_gen/all_results/results_direct_code_gen.csv`, `grasp_iterative_refinement/all_results/results_iterative_instances.csv`, `minigrid_*/metrics_*.csv` | GRASP: `run.py` → `eval.py`; MiniGrid: `minigrid_*/run.ipynb` |
| **Table 2** | Baselines + Naive/CoT/2-step CoT/IR + cost, hardest GRASP config | `results_baseline.csv`, `results_iterative_instances.csv`, `llm_solve_baselines/{grasp,minigrid}_results/results.csv`, `costs.csv`, `metrics_*.csv` | Baselines: `llm_solve_baselines/run_*_bench.py` → `eval_*.py`; IR as above |
| **Table 3** | IR reward/energy per refinement iteration (Figure 5) | `results_iterative_instances.csv`, `minigrid_*/metrics_*.csv` | same as Table 1's IR sources |
| **Table 4** | Greedy / Pseudocode Extension / Step-by-Step / IR (GRASP) | `results_greedy_extend_pseudocode.csv`, `results_step_by_step_intermediate.csv`, `results_baseline.csv`, `results_iterative_instances.csv` | `run.py` (per method) → `eval.py` |

**Metric definitions used everywhere:** GRASP reports *net energy*
`E_net = E_collected − N_actions × cost_per_step`; MiniGrid reports the environment *reward* (max 1.0).
Every cell is `mean ± 95% CI`, where `CI = 1.96 × std / √n`, rounded to two decimals (half away from
zero) as in the paper. **DG** is the initial program (refinement iteration 0); **IR** is the program
returned by Algorithm 1 — the best-performing refined iterate for every model. Table 2 averages over 100 instances per task (the hardest GRASP configuration; the first
100 MiniGrid seeds).

## Reproducing the raw results from scratch (optional)

The consolidated CSVs are already committed, so this section is only needed to rebuild them.

### GRASP (Direct Generation, Pseudocode Extension, Step-by-Step)
Run from inside `grasp_direct_code_gen/`:
1. In `run.py`, the `METHODS` dict selects which policy programs to execute
   (`direct_code_gen`, `greedy_extend_pseudocode`, `step_by_step_intermediate`, and the `baseline`
   greedy/random policies). Run it to produce per-instance JSON under `all_results/`:
   ```bash
   python run.py
   ```
2. In `eval.py`, set the `METHOD` constant to the method you just ran and execute it to score the
   JSON files into `all_results/results_<METHOD>.csv`:
   ```bash
   python eval.py     # writes results_direct_code_gen.csv (repeat per METHOD)
   ```

### GRASP (Iterative Refinement)
Run from inside `grasp_iterative_refinement/`: `python run.py` executes each model's per-iteration
policy (`model_codes_iterative/<model>/{a_basic,b,c,…}.py`), then `python eval.py` writes
`all_results/results_iterative_instances.csv`.

### MiniGrid (Unlock, Door-Key, Unlock-Pickup)
Open the task's `run.ipynb` (`minigrid_unlock/`, `minigrid_doorkey/`, `minigrid_unlock_pickup/`) and
run all cells. Each notebook executes the DG, IR, and Random/Greedy policies over 1000 seeds and
writes `metrics_<task>.csv`.

### Non-code prompting baselines (Naive / CoT / 2-step CoT)
Run from inside `llm_solve_baselines/` (**requires `OPENROUTER_API_KEY`**):
```bash
python run_grasp_bench.py       # queries the LLM, writes grasp_results/<model>/<method>/*.json
python eval_grasp.py            # scores them -> grasp_results/results.csv
python run_mini_grid_bench.py   # MiniGrid equivalent
python eval_minigrid.py         # -> minigrid_results/results.csv
```
Select the target model by editing the `MODEL` variable near the top of each `run_*_bench.py`.
